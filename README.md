# rust-local-agent · 学习路线

> 2026.10 — 2027.04，约 6 个月
> 目标不是「半年学会 Rust」，而是做出一个能实际使用的 Local Agent Harness，同时掌握支撑这个项目所需的 Rust。

## 三条原则

1. **每周必须产生一个可演示的差异**。这周的程序比上周多会一件事，能用 30 秒截屏说清楚。不是「这周学了 trait」。
2. **每节有最低通过线和加分项**。业余时间一定会有塌掉的一周，塌了就只做最低线，不欠债，直接进下一周。
3. **验收由命令判定，不由感觉判定**。跑得通就是过了，跑不通就是没过，不存在「大概懂了」。

时间预算：工作日 2 次 × 45min + 周末一次 2~3h，每周约 4~5 小时，半年累计约 100 小时。

- [x] 实测本地模型速度，记下 token/s（低于 10 就换更小的模型开发）

## 第一册 · 让程序跑起来（10 月）

> 本册目标：重新获得写 Rust 不害怕的感觉。Rust 知识只学卡住你的那些。

### 1.1（第 1 周）· 第一次对话

- 写什么：20 行，`ureq` 发一次 POST，打印模型回复
- 学什么：`main`、`String`、`?` 操作符。**不学 ownership**

- [ ] 最低线：`cargo run` → 输入一句 → 模型回一句
- [ ] 加分：加个 `loop` 让它能连续问

> 这一节故意放在最前面。把最枯燥的「捡回基础」放在唯一没有反馈的第一个月，那正是最容易断的位置。

### 1.2（第 2 周）· 有记忆的对话

- 写什么：把历史存进 `Vec<Message>`，每次整个发过去
- 学什么：`Vec`、`struct`、`#[derive(Clone)]`、**clone 到底**

- [ ] 最低线：问「我刚才说了什么」，模型能答对
- [ ] 加分：`/history` 命令打印当前历史

### 1.3（第 3 周）· 不再 panic

- 写什么：用 serde 正经解析响应，加 `anyhow`
- 学什么：`Option`、`match`、`Result`、`anyhow::Result`

- [ ] 最低线：**把 llama-server 关掉再运行**，程序打印友好错误而不是崩溃
- [ ] 加分：响应格式异常时也不崩

> serde 才是这个项目的第一个真·Boss，不是 ownership。嵌套 JSON 反序列化会卡你至少一个晚上，这是预期之内的。

### 1.4（第 4 周）· 命令 + 落盘

- 写什么：`/models`、`/clear`、`/save`
- 学什么：`enum` + `match`

- [ ] 最低线：`/save` 之后磁盘上确实有 `session.jsonl`，内容能看懂
- [ ] 加分：启动时自动加载上次的 session

### 月末（0.5 天）

- [ ] 不看旧代码，把 1.1 重写一遍
- [ ] 打 tag `v0.1`

> 写不出来的地方就是你以为懂了其实没懂的地方。

## 第二册 · 让模型伸出手（11—12 月）

> 本册是整个半年的核心。做完这册，你就真的做出 Agent 了，后面都是加法。

### 第 2 章 · 工具调用（11 月）

**2.1 · 只看不做**
- 写什么：定义 `tools` schema 发出去，**只观察不执行**
- 学什么：serde 的嵌套结构、`serde_json::Value`
- [ ] 最低线：日志里打印出模型返回的 `tool_calls`，参数是对的

**2.2 · 第一次伸手**
- 写什么：执行 `list_directory`，结果塞回去再问一次
- [ ] 最低线：问「D:\AI\models 里有哪些模型」，它答对了
- [ ] 加分：结果格式化得好看一点

> 这是整个半年最大的一个正反馈时刻。

**2.3 · 工具抽象**
- 写什么：加 `read_file`、`system_info`，用 trait 统一接口
- 学什么：`trait`、`Box<dyn Tool>`（lifetime 仍然不学）
- [ ] 最低线：新增一个工具只需改两个地方

**2.4 · 还债周 + 工具错误处理**
- [ ] 最低线：故意给不存在的路径，Agent 说「路径不存在」而不是崩溃
- [ ] 加分：把前三周欠的整理干净

### 第 3 章 · Agent Loop（12 月）

**3.1 · 循环起来**
- 写什么：把单次调用改成 `while` 循环
- [ ] 最低线：一句话触发**连续两次以上**工具调用

**3.2 · 刹车**
- 写什么：终止条件、最大轮次、死循环保护
- [ ] 最低线：给一个它做不到的任务，10 轮后干净地放弃并说明原因

**3.3 · 上下文管理**
- 写什么：工具结果超长时截断、历史压缩
- [ ] 最低线：让它读一个 5000 行的文件，不爆上下文、不明显变蠢
- [ ] 加分：对比 preserve_thinking 开关两种模式的表现

> 这是本地小模型最容易崩的地方，也是原版路线漏掉的重点。

**3.4 · eval 集 + 回放**
- 写什么：10 条任务写成 `evals.jsonl`，一条命令批量跑
- [ ] 最低线：输出 `7/10 passed` 这样的数字
- [ ] 打 tag `v0.5`

> 有了这个数字，后面所有改动都有了客观的正反馈来源。这是从「感觉能用」变成「确实能用」的分界线。

## 配套机制

这部分比路线本身更影响成败。

**每周仪式（10 分钟）**
一次 commit，message 写「现在它会做什么」，不写「学了什么」。半年后 `git log` 就是你的成长曲线。

**每月仪式（30 分钟）**
重写上个月第一周的代码 + 翻一遍 `notes.md` 的卡点日志，找重复出现的坑。间隔重写比重读有效得多。

**塌掉的那一周怎么办**
只做最低线，**绝不补课**。补课会滚雪球，这是业余学习最常见的死法。2.4 和 4 月后半段本来就是缓冲。

**什么时候该停下来重新评估**
连续三周都只做到最低线，说明每周 4~5 小时这个预算不现实。那就砍掉第三册，把目标缩到「第二册做扎实」。一个真正跑得通的 Agent Loop，比一个半成品的全功能 harness 有价值得多。

## 卡住了怎么办

按类型分流，别一律问 AI：

| 类型 | 去哪 |
|---|---|
| 编译不过（E0502 这类） | `rustc --explain E0502` + `cargo clippy`。**前三个月自己啃完** |
| 不知道用哪个 API | docs.rs / 问 AI，无思考损失 |
| 设计决策 | 要 2~3 个方案和取舍，自己选 |
| 逻辑 bug | 先打日志二分定位，这是调试能力 |

**时间盒**：自己想 15 分钟 → 搜 15 分钟 → 还不行才问 AI。

**问之前先写下你的猜测**（哪怕一行注释）。猜对了得到确认，猜错了会记很久。

**学习区 vs 工具区**：Agent Loop 主循环、工具分发、上下文管理策略 = 自己写；Cargo.toml、serde struct、CLI 参数解析、日志初始化 = AI 随便生成。判断标准：明天不看资料我能不能重写一遍？

**卡点日志**（`notes.md`）每次三行：

```
2026-10-12
问题：往 Vec 里 push 的时候编译不过
我的猜测：可能和引用有关
真实原因：for 循环里 iter() 借用了 vec，同时又想 push
```

半年后这个文件比代码更能说明你学到了什么。
